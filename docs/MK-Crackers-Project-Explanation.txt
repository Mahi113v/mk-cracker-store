1. PROJECT PURPOSE
------------------------------------------------------------------------------
Oru software, pala crackers companies use pannalam. Ovvoru company-kum:
  - thanoda online store (customers order / enquiry podalam)
  - thanoda products, stock, orders, users, reports
  - thanoda DATABASE (company-ku mattum), thanoda design, thanoda login
Neenga (product owner) "Platform Admin". Neenga company create pannum bodhu
database name kuduthaa, antha name la database automatic-ah create aagum, ellaa
tables-um serndhu. Antha company antha database-ai mattum thaan use pannum.


2. THREE LEVELS OF USERS
------------------------------------------------------------------------------
 A) PLATFORM ADMIN  (product owner - neenga)       login: /platform/login
    - Company create / edit / block, database create, design select,
      features on/off, company admin password reset, "Login as admin".
 B) COMPANY ADMIN / STAFF  (company-oda owner & staff)   login: /<code>/admin/login
    - Company admin = ellaa options. Staff = company admin tick panna options mattum.
 C) CUSTOMERS  (store users)                        login: /<code>/login
    - Products paakkalam, Quick Buy, cart, enquiry, UPI payment, screenshot upload,
      My Enquiries, Track order, Print bill.


3. ARCHITECTURE  (how company separation works)
------------------------------------------------------------------------------
                    +---------------------------+
   Browser  ------> |  React (Vite / built dist) |
                    +-------------+-------------+
                                  | every API call sends header  X-Company: <code>
                                  | (and login token)
                    +-------------v-------------+
                    |  Node.js / Express API     |
                    |  tenant middleware:        |
                    |   code -> company record   |
                    |   -> that company's DB     |
                    +------+----------------+----+
                           |                |
                  +--------v------+  +------v------------------------------+
                  |  MASTER DB    |  | COMPANY DBs (one per company)        |
                  |  mk_master    |  |  mk_crackers   sri_crackers  ...     |
                  |  companies    |  |  users, products, stock, orders ...  |
                  |  platform_    |  |  every row has  company_id           |
                  |  users        |  +--------------------------------------+
                  +---------------+

 Safety rules built in:
  1. Company code (URL)  ->  companies table  ->  db_name. Request antha DB-ai mattum thaan thoduvadhu.
  2. Login token-la company id (cid) irukku. Vera company-ku antha token use pannaa 401 ("Please login to this company").
  3. Every table-la company_id column irukku (default value = antha company id).
  4. Uploaded images: uploads/<companyCode>/... (company-wise folders).
  5. db_name unique: oru database-ai rendu companies use panna mudiyaadhu.

5. DATABASES
------------------------------------------------------------------------------
MASTER DB  (name = MASTER_DB in .env, default mk_master)
  companies        id, name, code (URL), db_name (unique), design (default|normal|current),
                   brand_color, features (JSON list), status (active|blocked|provisioning)
  platform_users   platform admin logins

COMPANY DB  (name = what you type while creating the company)   all tables have company_id
  users            role: company_admin | staff | user,   permissions (JSON list for staff),   status
  categories, brands
  products         code, name, brand, category, pack, mrp, discount_percent,
                   price (auto = mrp - discount), stock, low_stock_level, is_active
  product_images   many images per product, sort_order 0 = main image
  stock_movements  IN / OUT / SET / ORDER / CANCEL, qty, balance, reason, user, date
  orders           order_no (O-1001), user, total, status, payment_proof, address ...
  order_items      code, name, mrp, discount_percent, price, qty, amount (saved snapshot)
  settings         store name, phone, announcement, UPI id, banner
  schema_migrations  which migration files already ran

------------------------------------------------------------------------------
 - Discount bar: "% -> Apply to all" and "Reset"; each row-la thaniya discount-um maathalaam.

13. MIGRATION AND SEEDER  (important)
------------------------------------------------------------------------------
 Commands (project folder):
     npm run migrate          master DB + pending migrations on master and every company DB
     npm run migrate:status   shows [x] done / [ ] pending
     npm run seed             platform admin + demo companies (mk, sri) + sample data
     npm run setup            migrate + seed
     npm run db:fresh         DROP ALL + migrate + seed
 How it works:
   1. migrate creates MASTER DB (if missing) and runs database/migrations/master/*.sql
   2. For every row in companies, it runs database/migrations/tenant/*.sql inside that company DB.
      "schema_migrations" table remembers which files ran, so re-running is safe.
   3. {{CID}} inside the SQL is replaced with that company's id (used as the default company_id).
   4. New company from the platform screen runs the same tenant migrations automatically.
 To add a table / column later:  create  database/migrations/tenant/003_add_something.sql  and run  npm run migrate.

14. DEPLOYMENT CHECKLIST  (online server)
------------------------------------------------------------------------------
 1. Linux VPS (2 vCPU / 4 GB RAM is enough to start), Node 20 LTS, MySQL 8.
 2. Upload project, copy .env.example to .env, set DB_PASSWORD, JWT_SECRET (long random),
    CLIENT_URL = https://yourdomain.com , PLATFORM_EMAIL / PLATFORM_PASSWORD.
 3. npm install ; npm run migrate ; (npm run seed only if you want demo data)
 4. npm run build ; run API with PM2:   pm2 start server/server.js --name mk-crackers
 5. Nginx reverse proxy to port 5000 + free SSL (Let's Encrypt). Set  client_max_body_size 10M;
 6. MySQL user: create a dedicated user with CREATE/DROP/ALL on the databases (needed to create
    company databases from the platform screen).
 7. Backups: daily  mysqldump  of mk_master AND every company database + the uploads folder.
 8. Change every sample password. Block / delete the demo companies on a real server.


15. SECURITY NOTES
------------------------------------------------------------------------------
 - Passwords bcrypt hashed; JWT 7 days; all SQL parameterised.
 - Database names are validated (a-z, 0-9, _) before CREATE DATABASE.
 - Uploads: only JPG / PNG / WEBP / GIF up to 5 MB; Excel / PDF import 8 MB, read in memory.
 - Not included yet: forgot-password email flow, login rate limiting, audit log, 2-step login.
   Add these before selling to many customers.
